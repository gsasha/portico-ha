# transport-rs parity: house calls

Scope: `internal/house`: the house-call bridge, `-house-calls`.

The numbered differences of the whole port are indexed in [../../PARITY.md](../../PARITY.md); their numbers are stable (code comments, tests, the review log and the contract map cite them), so a new difference takes the next free number of its range and goes into the file of its subject. "Smoke" means `scripts/ipc_smoke.py` gave byte-identical output on both binaries, "unit" means a `cargo test` case. Reference: Go `transport/` at the branch point of `dev-764-rust-skeleton` (main `a52af72`), built with `golang:1.23`. Long table cells are shortened to a summary with the full text below the table.

## house calls (slice 9): the house-call bridge, `-house-calls`

**Row 167, Rust column, in full.** `Manager::open` holds an `OpenGuard`: if the future is dropped (the request task torn down), the reserved slot, the owner counts and every leg built so far are released. ### Go defects and oddities found (kept in the port; for DEV-770)

* **A call id of exactly `hso-` (no suffix) is accepted** (`validate` only checks the prefix); a 128-byte id passes, 129 does not. Python mints `hso-<uuid>`.
* **`Manager.Hold` has no IPC verb**: a library capability only (the design adds none), so the held-leg path is reachable only from the tests. Ported and golden-tested through the library API.
* **`isHouseID` and `routeFrame` parse the params twice**: a `media_frame` for a house id whose OTHER fields have the wrong type (`d`, `codec`, `reason` of the wrong JSON type) is `bad_params` with `wsMediaParams` in the text, the door path's own message. Kept.
* **A frames leg that stops sending closes through the hub's 5 s idle rule first**, so the call's own 10 s silence rule (documented as the one that "ends the call") only ever ends a call whose leg is a WebRTC leg, or whose frames leg sends nothing valid; with two silent frames legs the first to idle is the cause, and which one is not defined.
* **The counters line is written before the `lost` events** but the legs' own `media_closed` (written inside `Close`) come before both, so Python sees `media_closed`, then (log), then `house_leg_state lost`. Same order in Rust.
* **`Manager.Open` returns success for a call whose legs were both gone at once** (nothing is published, the slot is released, no event is sent for the open itself; the `lost` events follow). Python must treat the first `lost` as the end.

### Golden vectors

`tests/golden/house.json` (about 200 KB, `tools/gen_golden/house_gen.go`, `house_link.go`, `house_real.go`, replayed by `tests/golden_house.rs`): 31 scenarios of the real `house.Manager` through its exported API and 13 of the real `houseHub` (`cmd/portico-transport/house.go` itself is compiled into the generator through the symlink `house_real.go`, so it cannot drift; the real `wsMediaHub` is its door path, the real `wsmedia.Leg` its frames legs, a real pion `sfu.Session` its WebRTC legs). **Non-real parts** (also in the file header): in the manager scenarios the legs are the fakes of Go's own `house_test.go`; the clock the counters read is a fake one the scenario advances; the ids come from a list; `notify` and `join` are recorders; the IPC dispatch is registered on a real listener but the scenarios call the handlers directly; `callIDKey` (`house_link.go`) is repeated from `main.go`; the random session ids of the hub scenarios are printed as `house-S1`, `house-S2`, ... in order of first appearance; the answer SDP is printed as `<answer>`; frame contents come from the `wmGen` recipes. **Timing:** real time, generous waits (a settle of 15 ms after every step, 150 ms at the end, silence and idle timers of 500 to 700 ms against frames about 100 ms apart, widened after the review so a loaded host cannot move an event to another step); a step reports its events only at a `wait_events` step and at the end of the scenario, sorted (the order of two notifications written by different goroutines is not defined in Go either); two Go regenerations are byte-identical. A scenario avoids a race whose winner Go leaves open (two silent legs: which watchdog fires first). The replay fails if any step differs, and also if the number of scenarios changes.

(The generator is retired: see [tests_and_vectors.md](../tests_and_vectors.md).)

### Not verified (9)

* **No real phone, no real Python.** `house_bridge.py` and the two phones were not in the loop: frames come from a test client and the smoke script. A real WebRTC peer on a house leg was not run (the golden and the tests use the recorded offers and a garbage offer: the `sdp` event, never an `attached`); the str0m session itself is the one verified in slice 4b and INTEROP.md.
* **The 10 s silence rule of a frames leg is shadowed by the hub's 5 s idle rule** (above); the 10 s default is only exercised with short values (40 ms to 700 ms).
* **Races on real OS threads** are exercised by the multi-thread tests (30 rounds of opens against `close_all`, 40 concurrent opens); the replay of the golden is single-stream.
* **Both fakes of the manager golden** (Go's `hsLeg`, Rust's `FakeLeg`) are written separately from the same description; a defect common to both would not show. The hub scenarios use the real legs on both sides.
* RSS/CPU of four concurrent house calls: not measured. No deployment: the binary is not in the wheel and `house.py` is off unless Python starts the transport with `-house-calls`.
