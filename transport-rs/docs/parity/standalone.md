# transport-rs parity: standalone mode

Scope: the standalone/container mode: the TCP IPC, `-listen`, `-sip-from-env`, `-secrets-env`.

The numbered differences of the whole port are indexed in [../../PARITY.md](../../PARITY.md); their numbers are stable (code comments, tests, the review log and the contract map cite them), so a new difference takes the next free number of its range and goes into the file of its subject. "Smoke" means `scripts/ipc_smoke.py` gave byte-identical output on both binaries, "unit" means a `cargo test` case. Reference: Go `transport/` at the branch point of `dev-764-rust-skeleton` (main `a52af72`), built with `golang:1.23`. Long table cells are shortened to a summary with the full text below the table.

## standalone/container mode (slice 10): the TCP IPC, `-listen`, `-sip-from-env`, `-secrets-env`

Go: `internal/ipc/tcp.go` (150), `cmd/portico-transport/standalone.go` (218) and `secretsenv.go` (100); Rust: `src/ipc/tcp.rs` (the gate, the admission handshake, the listener), `src/ipc/mod.rs` (the listener is now an enum: Unix socket or TCP; the read loop, the dispatch classes and the write rules are shared), `src/process/standalone.rs` (`openIPC`, `parseAllow`, `sipConfigFromEnv`, `preloadSIP`, the adopt and detach wrappers, `serveReconnects`), `src/process/secretsenv.rs`, the wrappers' registration in `src/dispatch/mod.rs` (`configure_or_adopt`, `deconfigure_or_detach`, `Hub::preload_sip`) and `src/main.rs`. The mode is OFF unless `-listen` or `-sip-from-env` is given; with neither, `main` is what it was. Go drift check (`git log a52af72..origin/main -- transport/internal/ipc transport/cmd/portico-transport`): empty. `packaging/standalone/` is Docker packaging only (a Dockerfile that builds the Go binary into a `scratch` image, a compose snippet, a README): nothing in it is code to port, and it was not touched or run; a Rust image is the packaging slice. The Python client of this link (`custom_components/portico/door/remote.py`) sends the `auth` line first and treats `unauthorized` as fatal, which is what this server does.

**Row Bind rules, Behaviour column, in full.** `127.0.0.0/8`, `::1` and an IPv4-mapped loopback are loopback; the wildcard (empty host, `0.0.0.0`, `[::]`) is not; texts of the refusals (`ipc: refusing to listen on "A": loopback only until the non-loopback flag is set`, `ipc: a non-loopback listen address needs an allow-from list`, `ipc: the TCP listener needs a token of at least 24 characters`, `ipc: bad listen address "A": address A: missing port in address` and the other `SplitHostPort` texts, `address P: invalid port`) are Go's; an empty port binds port 0; the order of the checks is Go's (`-socket`/`-listen`, token file, allow-from entries, then the listener's own: token length, address, loopback, list)

### Go defects and oddities found (kept in the port; for DEV-770)

* **SERIAL ADMISSION (fixed in Rust, PARITY 302 and 400).** Go admits one connection at a time and a silent connection holds the accept loop for the whole 5 s window; an allowed (or, on loopback, any local) source opening silent connections back to back keeps the real hub from being admitted at all. Rust checks connections on tasks of their own, drops the OLDEST waiting one for a newcomer and never refuses a right token. The refusal log line (188) makes an attempt visible.
* **One slow connection holds the hub out (fixed in Rust, PARITY 302 and 400).** Go has no limit on attempts and no brake on guessing the token but the connection rate (serial) and the 24-byte minimum (a length, not entropy: `0000...` passes). Rust answers the third and later wrong token of one source within 10 s 5 s late (a source is never refused unread: on loopback every client has the same address, so that would lock the hub out).
* **The constant-time comparison returns at once when the lengths differ**, so the token's length leaks; harmless next to the minimum, kept.
* **Three token rules.** The `.env` reader refuses white space in a token; the token file and the variable do not (only trailing CR and LF of the file are trimmed), so a token with a space works from one source and not from the other.
* **`preloadedSet` can hold the empty key** (`preloadSIP` adds whatever `configureKey` returns); `has("")` is false, so it never matches. Kept; the Rust set refuses the empty key on lookup the same way.
* **A hub's `deconfigure` by `host` is not detached** (the wrapper looks only at `device_id`), so it reaches the normal handler and stops the preloaded driver if its registry id is that host. (Not checked here whether the Python hub always names `device_id`.)
* **A preloaded device that has left the registry** (after the shutdown drain) is answered `unknown_device` by the adopt wrapper, where the normal path would say `shutting_down`.
* **`sipConfigFromEnv` and the numbers**: `Atoi` accepts `+5004` and `0005004`; a negative or oversized value is passed to the driver, which refuses it. A value above 2^53 loses precision in the float64.
* **An accepted connection that sends nothing and closes at once makes `Serve` return nil,** so a flood of refused connections spins the accept loop without the 1 s pause an error gets.
* **`-secrets-env` accepts `export` followed by a tab or a space only**; `export KEY=` is another key.
* `GATE_SIP_PEER_TOKEN` is the name of the old app's peer token in the box's `.env`; the hub and that peer would share a secret if both were configured. Not a code defect; noted for the packaging slice.

### Not verified (10)

* **No real HA hub and no Docker image.** `custom_components/portico/door/remote.py` (the Python client of this link) and the Docker packaging were not run against the Rust binary; the auth line and the replies are those the Go server writes and the golden proves, the Python client was only read. `packaging/standalone/` still builds the Go binary.
* **IPv6 and DNS.** The dual-stack wildcard bind and a `-listen` host name other than `localhost` were not exercised on a host with IPv6 or a resolver of its own; the vectors run in a container.
* **Hardened beyond Go** (PARITY 302, 400): admission is not serial, a wrong token is slowed. Not load-tested; RSS and CPU of the container mode are not measured.
* **Timing of the 5 s window** is checked at 2.3 s gaps (accepted) and 5.2 s of drip, 5.6 s of silence (refused), on a quiet host; a very loaded host could move the edges.
* **The musl and aarch64 builds** were not rebuilt for this slice (`socket2` is the only new direct dependency and was already compiled in the tree).
