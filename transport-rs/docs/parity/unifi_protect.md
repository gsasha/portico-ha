# transport-rs parity: unifi_protect driver

Scope: the `unifi_protect` driver: the events websocket and API client (7a), the talk family and the hub talkback bridge (7b).

The numbered differences of the whole port are indexed in [../../PARITY.md](../../PARITY.md); their numbers are stable (code comments, tests, the review log and the contract map cite them), so a new difference takes the next free number of its range and goes into the file of its subject. "Smoke" means `scripts/ipc_smoke.py` gave byte-identical output on both binaries, "unit" means a `cargo test` case. Reference: Go `transport/` at the branch point of `dev-764-rust-skeleton` (main `a52af72`), built with `golang:1.23`. Long table cells are shortened to a summary with the full text below the table.

For 7b: `talk_dial.go` (the comment above; the behaviour it describes is Python's and `HangupCallWhy`'s, `ReasonedHangupper` exists in `driver/mod.rs`).

**What this driver is NOT** (the brief assumed otherwise): there is no login, no bootstrap, no cookie and no CSRF token, and no UniFi Protect "update packet" binary frame. The Go driver authenticates with the `X-API-KEY` header of the console's PUBLIC Integration API (`/proxy/protect/integration/v1/...`), reads JSON TEXT messages from `.../subscribe/events`, and drops binary messages. Self-signed certificates are handled by `verify_ssl: false` (`InsecureSkipVerify`), nothing else; `-host` and the secrets files are not used by it.

### Go defects and oddities found (kept in the port; for DEV-770)

* **A ring can get stuck for ever.** The ring timers return without ending a call that is `answering`; if the open then fails (or its context is cancelled) `AnswerTalkback` only clears `answering`, no timer is left, `stopTimers` keeps `endTimer` set so `onEnd` refuses a new one: the call never ends, `RingingCall` stays true and every later ring is ignored until a hang-up or Stop. Rust fixes it (difference 120); Go keeps it.
* **`Stop` drops a live ring without a word.** `endLocked` reports `ended` only while the driver is not `stopped`, and `Stop` sets `stopped` first and discards the call: a `deconfigure` (or a shutdown) during a ring never tells Python the call ended, so HA keeps it ringing until its own timeout. Pinned by the vector `timer: stop drops the live call silently` and the test `stop_closes_the_talkback_and_reports_nothing_for_the_live_call`. Candidate fix: report `ended` for a live call before the stop.
* **The backoff test runs after the sleep.** `watch` sleeps `backoff` and only then checks `time.Since(up) < stableAfter`, so the sleep counts as part of the connection's life: a connection that lived 29.5 s and slept 1 s is "stable" and the backoff does not double. Kept (`the_backoff_doubles_for_short_connections_and_resets_for_long_ones` uses lifetimes far from the edge).
* **The ring hold times are guesses.** `ring.go` says it itself: how long a real console keeps a ring event open is NOT verified; 10 s minimum and 60 s maximum are variables for that reason. Nothing here verifies them either.
* `readMessage` validates nothing about control frames (a ping that is not final, longer than 125 bytes, or masked is answered; Rust now refuses the first two, difference 470), allocates the announced length before reading it (up to 1 MiB per frame, per connection) and buffers a binary message to its end before dropping it. Ported as is, except the up-front allocation (difference 111).
* `read` sends a close frame after the console's own close (two closes in a row); harmless.
* The upgrade request has no `Origin` and sends `Host` with the port as configured (`nvr_host`); a console that is picky about either would refuse it; not seen.

## DEV-796 (Portico Rust security review): differences 470 to 475 that belong to this subject

* **470 (DEV-796 D9, deliberate difference): control frames follow RFC 6455 5.5, and empty continuation frames are bounded.** Go answers a ping of any size and a non-final control frame, and counts every frame, an empty continuation included, as life of the connection. The Rust decoder gives a protocol error for a ping, pong or close frame that is not final or carries more than 125 bytes (decided from the header, before any payload is held), and for more than 64 empty continuation frames in a row, so a hostile console cannot keep the watcher attached or have 1 MiB echoed as a pong. A compliant console is unaffected. Tests `control_frames_follow_rfc_6455_limits`, `a_run_of_empty_continuation_frames_is_cut`; the 35 Go goldens that differ are `GOLDEN_READ_DIFFERENCES` in `tests/golden_unifi.rs` (each must still differ, end in a protocol error and echo no pong over 125 bytes).
* **471 (DEV-796 D10, deliberate difference): an event id that is empty, over 128 bytes or has a character outside `[A-Za-z0-9._:-]` is ignored.** Go takes any non-empty id, stores it and reports it as the `call_id`. Real console ids are hex. Test `an_event_id_that_is_long_or_odd_is_ignored`; the golden frames 12, 13, 45, 46 and 69 are in `SCEN_DIFFERENCES` (each must still differ and report nothing).
* **475 (DEV-796 D5; no Go difference in wording): a talkback open that finishes after `stop` (or after a `stop` and a `start`) is closed, awaited and refused.** Go (`unifiprotect.go:193-233`) stores it with no check, so the session is nobody's to close; Rust checks `stopped` and a run counter before the console is asked and again at the store, and waits (bounded by `CLOSE_WAIT`) for the process to be reaped. `AnswerTalkback` still answers `no_such_call` when the run ended while the session opened. Tests `an_open_that_finishes_after_stop_leaves_no_session`, `an_open_on_a_stopped_driver_asks_nobody`, `an_open_that_spans_a_stop_and_a_restart_is_stale`, `a_stop_while_the_session_opens_answers_no_such_call`.
* **474 (DEV-796 D2, deliberate difference): a talkback sink on this host or a group address is refused.** Go's `validSink` checks the scheme and that a host exists. Rust also refuses (`talkback sink host is not allowed`) a host that is loopback, unspecified or multicast: IPv4 in any `inet_aton` form (`127.1`, `0x7f000001`, `0177.0.0.1`, `0`), a trailing dot, IPv6 (`::1`, `::`, `ff00::/8`, IPv4-mapped and IPv4-compatible such as `::127.0.0.1`, a zone ignored), an unbracketed IPv6 literal, a bracket that is not one whole IPv6 host (`[::1]:5060[]:7004`), a second `@` in the authority, leading-zero padding of any length, and the names `localhost`, `*.localhost`, `ip6-localhost`, `ip6-loopback`. Every other host stays valid (a camera on the LAN or elsewhere). Tests: `ffmpeg_args_and_sinks` (deny and allow lists); the goldens `rtp://[::1]:7004` and `udp://0.0.0.0:0` of `talk_helpers.json` are pinned by exact input in `golden_helpers`.
