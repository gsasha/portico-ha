# transport-rs: tests, golden vectors and the comparison with the Go binary

Moved from the README. Source comments say "see README.md" for the golden-vector generators: this is the section they mean (the recorded vectors are in `tests/golden/`).

> **The golden vectors are FROZEN (Go cleanup, D-20261123-cc1e).** The Go transport (`transport/`), the generator module `tools/gen_golden/`, `scripts/golden_check.sh`, the `td_go` helper and the pion `spikes/peer-go` were deleted once the Rust transport was the only one in use (D-20261119-c1af). `tests/golden/*.json` stay as recordings of what the Go code did, and the `golden_*.rs` tests keep replaying them; there is no longer a "fresh before merge" requirement. Everywhere below, `tools/gen_golden/...`, `scripts/golden_check.sh` and `transport/...` name files that now exist only in git history: **commit `bdd8e61`** (origin/main when the cleanup was written) is the last one that has them all. To regenerate you need that commit's `transport/` AND `tools/gen_golden/` together. Git tag `transport-v0.6.10` has `transport/` but not the generators, and its `transport/` still has the gate-sip observer packages that C5 (DEV-518) removed later, so vectors regenerated from the bare tag can differ from the committed ones. Changing a Rust behaviour a golden file pins means editing the vector by hand or retiring that test, with the reason in the PR.

## Golden vectors (`src/sip/`, `src/driver/`)

`tests/golden/*.json` are produced by the REAL Go `pkg/sip` (`tools/gen_golden/`, its own Go module
that `replace`s `../../../transport`) and replayed by `tests/golden.rs`: 87 request/response parse
inputs (each through both parsers), 39 SDP parses and 6 builds, 20 RTP parses and 6 marshals, 50
`AuthorizationFor` answers and 31 `VerifyDigestAuthorization` verdicts, 29 jitter-buffer scripts
(in order, reordered, duplicated, lost, wraparound, resync, overflow) and 60 wire scenarios
(`Dial`, `AnswerIncoming`, `Respond`, `Registrar` against a scripted loopback peer; 120 datagrams
compared byte for byte with the random branches, tags, Call-IDs and ports masked). They were
generated by `scripts/golden_check.sh` (a pinned Go image, `-mod=readonly`); that generator is retired, see the note at the top.

Slice 3b-1 adds `gss_server.json` and slice 3b-2 `gss_dial.json` (below). Slice 3a adds six files, replayed by `tests/golden_driver.rs`, produced by `tools/gen_golden/driver_gen.go`
and `gss_gen.go` (the unexported Go functions are reached with `//go:linkname`, see `gss_link.go`; `transport/` is
not edited): `driver_caps.json` (the configure reply bytes of all 13 shipped-driver cases of
`capabilities_golden_test.go`, 6 bare `Capabilities` values, 3 real REGISTER flows for `CanDial`, sentinel texts),
`gss_config.json` (175 config objects, 56 accepted and 119 refused, plus 952 `allowed()` probes), `gss_media.json`
(67 SDP offers through `chooseMedia` and 96 `sdpFor` answers), `gss_alaw.json` (all 256 decodes, all 65536 encodes,
210 sample and converter vectors), `gss_audio.json` (30 `CallAudio` scripts, 184 steps: frames, drops, claim,
attach, detach, call end) and `gss_driver.json` (5 scripts, 41 calls of the driver glue before Start). Everything
but `digest.json` regenerates byte-identically (the jitter scripts run in real time on
the Go side and were stable over repeated runs); `digest.json` embeds random nonces and cnonces,
so it changes on every run (the Rust test recomputes the cnonce-dependent headers from them); `scripts/golden_check.sh` therefore compares `digest.json` with those nonces, cnonces and the responses over them masked and every other file byte for byte (R2-106: run twice, `digest` printed "fresh" both times, and a changed `known_response` made it print DIFFERS).

`gss_server.json` (slice 3b-1, `tools/gen_golden/server_gen.go` + `server_scen.go`, replayed by
`tests/golden_server.rs`) holds 82 scenarios recorded from the REAL Go `gate_sip_server` driving a
scripted fake station over UDP loopback: registrar (401/200, wrong digest, forged and expired
nonces), INVITE ring, answer, media in both codecs, 486, retransmits before and after the answer,
ring limit, CANCEL, BYE, orphan grace, goodbye, `Hangup`, `HangupCall`, `Stop` during a call and a
ring, attach and answer refusals, the strict RTP source rule, the backpressure counters (the real
RTP loop), `allow_from`, the `AnswerWithAudio` path with the two-way audio, the CanDial republish
and the password floor. Each scenario is a list of operations and the result of every operation
that observes something: every datagram the server sent (the tags, branches and nonces the server
mints and the ports masked), RTP header fields and payload digests, counters, sink events, return
values and error texts. The Rust replay requires every result to be equal. Regenerate just these
(about 70 s, real time; the other generators are unchanged) (generator retired: see the note at the top).

Two consecutive runs gave byte-identical files. What is not the real Go code: the timers the Go
tests overwrite (`ringLimit`, `orphanGrace`, `regTTL`) and the `NonceStore` clock are set by
`unsafe`/reflection (`gss_link.go`), because `Configure` takes whole seconds; everything else goes
through the exported API.

`gss_dial.json` (slice 3b-2, `tools/gen_golden/dial_gen.go` + `dial_scen.go`, replayed by the same
`tests/golden_server.rs`) holds 52 scenarios of the REAL Go server placing the call to a scripted
station: no challenge, 401 and 407 answered with the credentials, a repeated and an unanswerable
challenge, six station refusals (403, 404, 480, 486, 500, 603), ring timeout and CANCEL, the caller
cancelling, a 200 crossing the CANCEL, a wrong codec, no media port, no or bad SDP, `c=` outside
`allow_from`, a media host that is not the station, RTP before the answer, a retransmitted 200,
foreign host / Call-ID / CSeq / method responses, the station's CANCEL and BYE, our hang-up, the
client leg leaving, the attach window, the cap, `Hangup` while ringing out, `Stop` during the ring
and while talking, an inbound INVITE while dialling or talking, a dial while an inbound call rings,
the refusals, CanDial lapsing and returning, and a station that REGISTERs from another host. The
station is scripted blind, so a `reply` operation builds its answer from the last datagram the
station received with a given method; the branches the server mints are numbered by first
appearance (`ord_branches`), so a scenario sees that the CANCEL carries the INVITE's branch and
that the ACK of a 200 has one of its own. Package-private timers (`dialRing`, `cancelW`, `dialCap`,
`dialAtt`, `regTTL`, `cfg.ringLimit`) are set by reflection, as 3b-1 does. Regenerate just these
(about 90 s): the same command as above with `-e GEN_ONLY=dial`. Two consecutive runs were
byte-identical, and the generator changes left `gss_server.json` byte-identical.

The rehearsal (`tests/rehearsal/`, copied unchanged from `transport/pkg/driver/gatesipserver/testdata`)
replays the 22 recorded dialogues against the Rust server and diffs the normalised transcript with
the one recorded from the real gate-sip: a MATCH dialogue must have an empty diff and a DIFFERS
dialogue must reproduce the diff the Go test pins, byte for byte.

`sfu_*.json` (slice 4a, `tools/gen_golden/sfu_gen.go`, `sfu_policy_gen.go`, `sfu_link.go`, replayed by
`tests/golden_sfu.rs`) come from the REAL `transport/internal/sfu`: G.711 and the converters (all 65536
encodes, all 256 decodes, 272 frame vectors incl. odd lengths and all pairs of boundary values),
G.722 (`g722Encoder`/`g722Decoder`, i.e. the real `gotranspile/g722`: 27 scenarios / 292 frames of tones,
chirp, white and low-level noise, silence, full-scale squares and Nyquist alternation, DC, impulses, a burst
between silences, speech-like signals up to 2 s, frame sizes 10/20/40 ms and mixed, with the encoder and
decoder state carried over the frames; 263 decoder-only scenarios with every byte value; 10 odd lengths,
which PANIC in Go and are recorded as such), the real `uplinkBuffer` driven in real time (33 scripts: 5 to
120 ms packet sizes and the ptime/delay clamps, in order, reordered, lost, late, overflow, wraparound,
resync, silence byte 0xFF / G.722 / set too late, empty payloads, close), and a real `sfu.Session`'s answer
to 43 offers (offers written by pion peers in different codec orders, edits of them, and the Chrome 124 and
Firefox 153 offers of the S1b spike). Nothing in `transport/` is edited. The generator is in the same Go
module as before, whose module path is now `.../transport/tools/gen_golden` (so that Go lets it import the

The files total 3.2 MB (the G.722 scenarios are most of it).

Two consecutive runs were byte-identical.

## Comparing with the Go binary

`scripts/ipc_smoke.py <binary>` (Python 3, standard library only) starts the binary on a temporary
socket, plays a fixed script of requests and prints the normalized responses, exit codes and
socket-file state. Run it on both binaries and diff the outputs:

```sh
docker run --rm -u $(id -u):$(id -g) -v <checkout of commit bdd8e61 or tag transport-v0.6.10>/transport:/src -v /tmp/out:/out -w /src -e HOME=/tmp \
  -e GOCACHE=/tmp/gocache -e CGO_ENABLED=0 golang:1.23-alpine \
  go build -o /out/portico-transport-go ./cmd/portico-transport
python3 -I transport-rs/scripts/ipc_smoke.py /tmp/out/portico-transport-go > go.txt
python3 -I transport-rs/scripts/ipc_smoke.py transport-rs/target/release/portico-transport > rs.txt
diff go.txt rs.txt
```

The expected differences are the rows marked "smoke diff" in PARITY.md (as of slice 10: the answer structure; the script also sends 18 `configure` refusals of `gate_sip_server`, which match Go byte for byte).
Since slice 3b-1 it also runs a valid `gate_sip_server` configure, a fake station over UDP loopback
(REGISTER, INVITE, BYE), the device verbs, the notifications and `deconfigure` through the IPC. Since
slice 3b-2 the station is also dialled three times (an INVITE challenge answered and the call hung up through the
IPC, a station refusal, a station hang-up). Since slice 4b the `webrtc_flow` section sends the `webrtc_*` verbs: 14 error
paths and garbage offers compare byte for byte, 7 compare by error code (the library's own text, and the four follow-ups of a refused offer, PARITY.md difference 79), and 3 valid offers (the
recorded Chrome 124 and Firefox 153 offers, and a renegotiation) compare by structure, since the SDP differs by library.
The reference transcripts of these flows are `conformance/transcripts/*.txt` (recorded from the Go binary, 17 groups, one per flow or process case). The Rust binary
prints the same lines apart from the 10 patches of `conformance/transcripts/rust_patches.json` (11 Rust lines in place of 10 Go lines; each tied by `contract_runner.py --audit`
to a `DIFF-*` entry of `../contract/transport_ipc_v1.json` and a numbered PARITY row): the four follow-ups of a refused offer (79), `a=setup:passive` instead of pion's `active` (61),
`G722/8000` for Firefox's `G722/8000/1` (66), and the standalone flow's log lines (186, 188). None is in the observer section. The count of lines is whatever the transcripts hold
(`wc -l`); it is no longer quoted here.

## Standalone/container mode (slice 10): tests and vectors

`src/ipc/tcp.rs` is `internal/ipc/tcp.go` (the IPC over TCP, token-authenticated), `src/process/standalone.rs` is `standalone.go` (`openIPC`,
`parseAllow`, `sipConfigFromEnv`, the preloaded-device wrappers, `serveReconnects`) and `src/process/secretsenv.rs` is `secretsenv.go`. The mode is
OFF unless `-listen` or `-sip-from-env` is given. `cargo test` adds `tests/standalone.rs` (all 6 Go tests of `tcp_test.go`, all 5 of
`standalone_test.go`, all 8 of `secretsenv_test.go`, plus what the port adds), the unit tests of `ipc/tcp.rs` and `tests/golden_standalone.rs`,
the replay of `tests/golden/standalone.json` (83 KB): `sipConfigFromEnv` (33 environments), `parseAllow` (52 strings), `openIPC` (44 calls,
real loopback listeners), `.env` files through `loadSecretsEnv` and `withSecretsEnv` (59), the adopt / detach decisions (20) and `preloadSIP` (5),
and 85 conversations (116 phases) with a real Go TCP IPC server: every shape of first line, the 1 MiB line limits, the allow-from check and the
5 s authentication window. The generator compiles the REAL `standalone.go` and `secretsenv.go` through the symlinks `standalone_real.go` and
`secretsenv_real.go`; the other parts are listed in the header of `standalone_gen.go`. Regenerate (two runs are byte-identical; no real secret is in
the file) (generator retired: see the note at the top).

`scripts/ipc_smoke.py <binary> standalone` runs the `standalone_flow` alone: the hub's TCP session against a binary started with `-listen`
and `-sip-from-env` (refused first lines, a wrong token, the adopt and the detach, the reconnect, SIGTERM), `-secrets-env`, and 18 start-up
refusals; 104 lines, identical on the Go and the Rust binary (ports, temp paths and the log timestamp are masked).

Deploying it: the mode is for the container image only. HA's own subprocess still uses `-socket`; nothing in the wheel path changes. The
container needs `PORTICO_IPC_TOKEN` (or `-ipc-token-file`, or `-secrets-env`) of at least 24 characters, `-listen` on a loopback address or
`-ipc-allow-non-loopback` together with `-ipc-allow-from`, and, for the gate trial, `-sip-from-env` with `PORTICO_SIP_*`. The stream is not
encrypted: carry it over loopback, a private docker network or a tunnel. The cross-build, the wheels, the release tag scheme, the rollback and the dry-run release script are in `packaging/rust/` (see its README); `packaging/standalone/Dockerfile.rust`
is the container image around this binary (the Go `Dockerfile` and the compose snippet are unchanged). Nothing is published or pinned, and a live cut-over is the maintainer's decision.
